# Синк v2: остатки, цены и карточки на пять площадок

Статус: принято владельцем 25.09.2026 (допрос `/grill-me`).
Бизнес-решение: `business-os/decisions/2026-09-25-sinhronizaciya-ostatkov-cen-i-kartochek.md`.
Заменяет по мере переключения: `sync/` (v1) и `docs/SYNC_ARCHITECTURE.md`.

## 1. Цель и границы

Одна система держит остаток, цену продавца и карточку товара на пяти площадках:
**WB** (мастер), **Ozon**, **Яндекс.Маркет**, **Яндекс KIT** (kit42191), **сайт**
kotelnikovartifact.ru. Код пишется так, чтобы перенестись в finstock копированием
папок: те же слои, те же правила денег, тот же стек.

Вне границ: склад и документы (приёмка, списание) — это finstock; финансы и P&L —
finstock; FBO-запасы площадок.

## 2. Принятые правила (коротко, со ссылкой на пункт решения)

| 4 | Заказ любой площадки списывается со всех остальных, включая WB. На WB руками — только физика. |

| 10 | KIT, сайт — прайс × (1 − k_спп); k — медиана СПП магазина за 30 дней из финотчёта WB, раз в неделю, гистерезис 3 п.п.; пол — нетто WB + доставка; потолок — прайс. |

| 13 | Ozon: раз в неделю продлить `min_price_for_auto_actions_enabled`, пересчитать `min_price`; «Хочу скидку» — на кнопки. |
| 14 | ЯМ: `minimumForBestseller` не задаётся никогда (его отсутствие в записи стирает значение). |

| 17 | Правки контента: Ozon/ЯМ — через подтверждение «было → станет»; KIT — без; сайт берёт контент с WB сам. |

## 3. Стек и раскладка

Как в finstock (`finstock/CLAUDE.md` — обязательное чтение перед кодом):
TypeScript strict, Node ≥ 22 на VPS (26 — когда будет на VPS), PostgreSQL, Drizzle, Vitest,
npm workspaces, запуск через `tsx`. Относительные импорты без расширения.

```
sync2/
  packages/
    domain/      чистые функции: пул, цены, СПП-коэффициент, диф карточки. Ни сети, ни базы.
    platforms/   адаптер на площадку: wb, ozon, ym, kit, site. Единственное место с сетью.
    db/          схема Drizzle, миграции, репозитории.
    shared/      типы, money (копейки), конфиг.
  apps/
    worker/      джобы, планировщик, CLI (`sync2 <job> [--apply]`), Telegram-бот.
```

Название папки `sync2/` — рабочее; при переносе содержимое ложится в `finstock/packages/*`
и `finstock/apps/worker`.

### Правила кода (из finstock, без переоткрытия)

- Деньги — только целые копейки, поля `*Minor`, `bigint` в режиме `number`. Рубли — только
  в маппере площадки на границе (`rubToMinor`).
- Слои: площадка → адаптер → сырьё (только дописывается) → домен (чистый) → действие.
- Защита от дублей — уникальными индексами, не проверками в коде.
- Адаптер на площадку, не универсальный клиент. Наружу — адаптер и типы ошибок, не `requestJson`.
- Запись на площадки — только через `PlatformWriter`, который читает выключатель
  `SYNC_WRITE_MODE=off|dry-run|apply` и флаг площадки в таблице `channels`. Выключатель
  подключается и покрывается тестом **до** первой пишущей функции.
- Лимиты — по спеке для нашего типа токена (у WB базовый: цены 4/час, календарь акций 1/час,
  финотчёт 2/сутки) и на аккаунт, а не на токен. Никаких слепых повторов на 429:
  читать `X-Ratelimit-Retry` / `retry-after`, повторять только короткие окна.

## 4. Данные (PostgreSQL)

Минимальный набор; имена — по конвенциям finstock.

| Таблица | Назначение | Ключ уникальности |
|---|---|---|
| `channels` | 5 площадок: id, код, режим записи (off/dry-run/apply), склад площадки | `code` |
| `products` | товар: баркод, артикул WB, nmID, название, категория WB | `barcode` |
| `listings` | товар на площадке: offer_id/sku/variant_id, статус карточки, хеш контента | `(channel_id, barcode)` |
| `stock_snapshots_raw` | сырые снимки остатков площадок (только дописывается) | `(channel_id, taken_at)` |
| `orders_raw` | сырые заказы всех площадок со статусом | `(channel_id, external_id, line)` |
| `pool_items` | состояние пула на баркод: base, wb_expected, … (как `PoolItemState` finstock) | `barcode` |
| `pool_events` | журнал пула: order, cancel, wb_signal, cold_start, manual | `(order_id, kind)`, `(barcode, kind, snapshot_at)` |
| `agreed_prices` | прайс: цена продавца WB, уступка WB, источник, кто/когда | `barcode` + история в `agreed_price_history` |
| `price_targets` | рассчитанные цены на площадку и что реально стоит | `(channel_id, barcode, computed_at)` |
| `spp_coefficients` | недельный коэффициент СПП, окно, число продаж | `week` |
| `decisions` | вопросы на кнопках: тип, полезная нагрузка, статус, кто/когда ответил | `id`; `(kind, subject, open)` частичный уникальный |
| `runs` | журнал запусков: job, run_id, начало/конец, итог, счётчики, ошибки | `run_id` |
| `writes` | каждая запись на площадку: было → стало, ответ, проверка применения | `(run_id, channel_id, barcode, field)` |

Состояние v1 (`data/state/inventory.json`, `prices-state.json`) импортируется разово
командой `sync2 import-v1`, дальше не читается.

## 5. Остатки

**Домен.** Берётся алгоритм `reconcilePool` из `finstock/packages/domain/src/pool.ts`
(копией с тестами, с сохранением имён) и расширяется:
- заказы всех четырёх зеркал (Ozon, ЯМ, KIT, сайт) — `PoolOrder`;
- различение «отмена до отправки» и «возврат после доставки» — по таблице статусов
  площадки в адаптере (`OrderLifecycle = open | shipped | cancelled_before_ship | returned`),
  а не регуляркой по строке. Только `cancelled_before_ship` даёт +1;
- цель на площадку = пул, кроме WB, где цель = пул и запись идёт на FBS-склад.

**Адаптеры (чтение заказов / запись остатка):**

| Площадка | Заказы | Остаток |
|---|---|---|
| WB | marketplace-api `/api/v3/orders` + `/orders/status` (не statistics) | `PUT /api/v3/stocks/{warehouseId}` |
| Ozon | `/v3/posting/fbs/list` (только FBS) | `/v2/products/stocks` |
| ЯМ | `/v2/campaigns/{id}/orders` (limit/page_token только в query) | `PUT /v2/campaigns/{id}/offers/stocks` |
| KIT | `GET /v1/orders` | `POST /v1/variants/stocks/bulk_update`, склад «Мой склад Краснодар» |
| Сайт | новый закрытый служебный API сайта: `GET /api/internal/orders?since=` | `PUT /api/internal/stocks` |

**Сайт.** В проекте `kotelnikovartifact` добавить два служебных эндпоинта с токеном
в заголовке и отключить `sync-stocks` и `sync-prices` (контент — `sync-products` — остаётся).

**Ключ товара на площадке** — баркод и артикул WB, адаптер шлёт оба там, где площадка их
различает (урок v1 от 10.09: офферы ИП заведены по артикулу).

**Ограничители** (из v1, уточнено 26.09): abort при > 120 разных баркодов с изменением остатка или > 20 баркодов, уходящих в ноль, за прогон; при сбое чтения
заказов любой площадки — запись остатков не делается, алерт.

## 6. Цены

**Прайс.** Стартовое наполнение — `reports/reprice-2026-07-18.csv` (колонка
`WB_витрина_неизм`) с поправками дрейфа 19.07; всё в копейках. Правка — только через
кнопку «принять» или CLI `sync2 price set <barcode> <₽> --reason`.

**Сторож WB.** Раз в 30 мин (в пределах 4 запросов/час базового токена, общий бюджет с
остальными джобами цен) — снимок `discounts-prices` → сравнение `discountedPrice` с
прайсом → при расхождении > 1% открытый `decision` «принять / автоакция». Повторно по
тому же товару не спрашивать, пока вопрос открыт.

**Расчёт цен (домен, чистый, `packages/domain/src/pricing`):** перенос `sync/src/pricing.ts`
(`computeTarget`, `fitBase`, округление ₽…90) в копейки, плюс:
- ЯМ: ставка = FEE + перевод платежа + min(5%, 1 000 ₽ / цена);
- KIT/сайт: `price = clamp(прайс × (1 − k), пол = нетто_WB + доставка, потолок = прайс)`;
- WB: минимальная цена для шаблона = ceil_руб(прайс × (1 − уступка)).

**Запись:** Ozon `price/old_price/min_price` + `min_price_for_auto_actions_enabled=true`,
автоакции DISABLED; ЯМ — бизнес-уровень `offer-prices/updates` с `discountBase` всегда и без
`minimumForBestseller`; KIT `prices/bulk_update`; сайт — служебный API. Анти-флаппинг 2%,
кап 60%, abort > 400 изменений, проверка применения перечитыванием не раньше 3 мин.

**Коэффициент СПП:** раз в неделю `finance-api sales-reports/detailed` (2 запроса/сутки)
→ медиана поля `spp` по выкупам за 30 дней; при числе выкупов < 10 коэффициент не
меняется.

## 7. Защиты

- **Шаблон WB** — `sync2 wb-min-prices <шаблон.xlsx>`: заполняет два столбца по артикулу,
  остальное в файле не трогает, пропуски — списком с причиной. Напоминание в Telegram при
  изменении прайса, новом товаре или автоакции, пойманной сторожем.
- **Ozon** — джоба `ozon-guard` раз в неделю: `timer/update` по всем товарам, `min_price` из
  расчёта; `discounts-task/list` каждые 30 мин → `decision` с нетто и кнопками
  «одобрить / отклонить» → `approve`/`decline`.
- **ЯМ** — `minimumForBestseller` отсутствует в любой записи цены (тест на сериализатор).

## 8. Карточки

Перенос логики `sync/src/cards-ozon.ts`, `cards-ym.ts` + KIT:
- создание при первом положительном остатке; ключ оффера — артикул WB, если уникален,
  иначе баркод (`mirrorOfferId` v1);
- категории — только `data/mappings/category-map.json`, ювелирные — чёрный список;
- санитайзер текстов: FB_JEWELRY («серебро», «925»), FB_ORIGINAL («подлинный», «оригинальный»);
  карточки с «Серебро 925» в характеристиках WB — не зеркалятся;
- правки: хеш контента WB (название, описание, характеристики, фото) против `listings.content_hash`;
  Ozon/ЯМ → `decision` с дифом, KIT → сразу.

## 9. Telegram

Бот @kotelnikovartifactbot, группа `chat_id -1004395280612`. Приём нажатий — long polling
`getUpdates` в воркере (публичного HTTPS на VPS нет). Кнопки принимаются только от ID из
`TELEGRAM_APPROVERS`; под сообщением после ответа — «решено: кто, когда». Алерты делятся на
**действия** (кнопки), **события** (заказ, возврат, сбой) и **сводку** (раз в сутки);
сообщение «всё хорошо» не шлётся.

## 10. Наблюдаемость и тесты

- Лог — pino, JSON, у каждого запуска `run_id`, в `runs` — итог и счётчики; `writes` — каждое
  «было → стало» с ответом площадки.
- Юнит-тесты домена рядом с кодом. Контрактные тесты адаптеров на записанных ответах
  (`packages/platforms/src/*/fixtures`), включая 429, пустые страницы, пагинацию ЯМ.
- Тест выключателя записи: при `off` и `dry-run` ни один `PlatformWriter` не делает сетевой
  запрос.
- Джоба `compare-v1` на время параллельного режима: цели v2 против того, что выставил v1,
  расхождения — в сводку.

## 11. Порядок работ

0. **Заплатки v1 (до нового синка):** `orders` каждые 5 мин; разовый шаблон минимальных цен
   WB из таблицы 18.07 (−10%) до 01.10; разовое продление флага Ozon + `min_price` до 04.10.
   Записи — после предпросмотра и «да» владельца.
1. **Каркас + остатки.** Монорепо, база, лог, выключатель, адаптеры пяти площадок на
   чтение; пул в `dry-run` рядом с v1 → сверка ≥ 3 суток без расхождений → запись KIT и
   сайта (их в v1 нет) → переключение Ozon/ЯМ/WB с отключением в v1.
2. **Цены.** Прайс, сторож, кнопки, расчёт, запись на четыре зеркала, СПП-коэффициент;
   отключить чтение цен WB на сайте.
3. **Защиты.** Команда шаблона WB, `ozon-guard`, «Хочу скидку».
4. **Карточки.** Создание, правки с подтверждением, KIT без.
5. Удалить `sync/` и крон v1.

Каждый этап — отдельный план в `docs/superpowers/plans/` перед кодом.

## 12. Открытые вопросы (не блокируют этап 1)

- Персональна ли СПП — влияет на точность k, не на устройство.
- Кнопка ЛК WB «Добавить все подходящие» снимает минимальные цены — синк это не увидит,
  только сторож постфактум.
- Статусы заказов KIT и сайта для `cancelled_before_ship` / `returned` — уточнить по спеке KIT
  и коду сайта в плане этапа 1.
